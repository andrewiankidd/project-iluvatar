#### About
Continuing with my theme of separation of responsibilities and 'reproducible everything' I thought a second cluster would be a good idea.

This cluster would be responsible for hosting actual workloads and services I plan on using (or offering) day-to-day.

This cluster will be ideally replacing my existing ProxMox/VM/Docker hybrid setup nightmare.

##### Overall goals:
 - Small, Redundant, Reproducible cluster
 - Low power consumption (Relatively)
 - Stackable/Rackable
 - Separate OS and Data disks
 - Should be somewhat 'cool' too

## Software Configuration

### OS: Talos Linux
![talos logo](../../../assets/docs/architecture/talos.png)

The main cluster netboots Talos Linux volumes provided by the Pis. Nodes stay immutable and ephemeral—pull the power or reprovision hardware and Talos simply rehydrates from Git-defined state. There’s no SSH shell, and every change flows through declarative manifests.

Omni installs each machine from the same Image Factory schematic it netbooted, with the lab CA and Omni's join config baked in, so a machine still trusts the lab after the install reboots it.


### Configuration: Talos Machine Configuration
![talos logo](../../../assets/docs/architecture/talos.png)

Talos supports declarative config out of the box, no need for another tool here.


### Orchestration: Kubernetes (k8s)
![k8s logo](../../../assets/docs/architecture/k8s.png)

Talos ships a vanilla, upstream-compatible Kubernetes control plane. Once a node joins, the kubelet comes online automatically, Argo CD syncs workloads, and Longhorn attaches storage, all without manual tinkering. It’s the same Kubernetes ecosystem I use elsewhere, just delivered in a sealed, API-first package.

### Deployment: ArgoCD
![argo logo](../../../assets/docs/architecture/argo.png)

Argo CD is a Git-driven deployment controller for Kubernetes that continuously applies the desired application state stored in a Git repository.

It watches manifests, Helm charts, or Kustomize configs and ensures the cluster matches them, handling updates, rollbacks, and drift detection automatically.

It's widely used for GitOps workflows where Kubernetes configuration, application releases, and operational changes are all version-controlled and applied declaratively.

arda runs no Argo CD of its own: ainur's deploys to it, as ainur is the control plane for both clusters. One UI and one Dex login at `argocd.kidd.network`, with arda's apps under the `arda` project and root app (user-data: `24-arda-apps.yaml`). `arda-bootstrap` registers arda there as the cluster named `arda`: a service account with cluster-admin on arda and its token, and arda's API address and CA, read from arda itself. ainur's Argo CD talks to arda's API directly, not through Omni's proxy. While ainur is down, arda keeps running but nothing syncs to it.

### Workloads: ArgoCD Applications
![Screenshot of ArgoCD application list view](../../../assets/docs/arm-cluster-argocd-applications.png)
> ArgoCD: How heroes ship

Each is an Argo CD Application under [`src/manifests/arda`](https://github.com/andrewiankidd/project-iluvatar/tree/main/src/manifests/arda). Anything that cannot be in this public repo (tokens, who plays) comes from the bootstrap VM's `.env`, as a Secret per app; nothing is created by hand.

#### Longhorn
[`src/manifests/arda/longhorn.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/longhorn.yml)
- The default storage class, three replicas across the nodes' SATA SSDs.
- Argo CD rebuilds every Kubernetes object, so volume data is all that needs backing up.

#### Backups
[`src/manifests/arda/kyverno-policies/volsync.yaml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/kyverno-policies/volsync.yaml)
- **Every Longhorn volume, nightly at 03:00**, to the `arda-backups` bucket in Cloudflare R2: VolSync copies a Longhorn snapshot with restic, encrypted with `ARDA_VOLSYNC_PASSWORD`. Nothing to set up per app: a Kyverno policy gives every new claim its backup, chart-made ones included.
- **Kept**: the last 5 runs, then 7 daily, 4 weekly and 6 monthly.
- **Restored by itself**: each claim is created *from* its latest backup, so a rebuilt arda waits for its data instead of starting empty. A claim with no backup yet starts empty.
- **Opting out**: `kidd.network/backup: "false"` on the claim. Only the media library (it can be fetched again) and Paperless's inbox (files only pass through) are.
- **Watched**: `VolumeBackupMissing` alerts to your phone through ntfy when a volume's backup falls behind.
- Omni's data on ainur is backed up the same way, to `arda-backups/omni`, nightly at 03:32.

#### Home Assistant
[`src/manifests/arda/homeassistant.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/homeassistant.yml)
- The start of replacing Nest and the Hue cloud, at `homeassistant.kidd.network`, on the LAN only. It is the container image, not Home Assistant OS, so there is no Supervisor and no add-ons: what would be an add-on (speech, an LLM, a Zigbee bridge) runs on arda as an app of its own.
- It runs on the node's own network, so its discovery hears the LAN's mDNS and SSDP: the Hue Bridge, the Google speakers and Chromecasts, and Matter devices all show up. That takes a privileged namespace under Talos's Pod Security, and it listens on the node's address as well as behind Traefik.
- Nothing to click through. `configuration.yaml` comes from Git (name, time zone, units, the Dex login), and so do its HTTP settings: since 2026.11 Home Assistant keeps those in its own store and reads them from YAML only once, so the Deployment writes `http.json` into that store at every start. They trust arda's pods and nodes as proxies, so Traefik's forwarded requests are accepted. A CronJob (`setup.py`) does onboarding through Home Assistant's API, making the owner `admin` with `ARDA_HOMEASSISTANT_PASSWORD`, so the first-visit page never appears. It then adds the integrations below and the voice pipeline, each only if missing. The home's location comes from `ARDA_HOMEASSISTANT_LATITUDE`/`_LONGITUDE` if set (kept out of a public repository), or the Settings > System > General map.
- Everything else made in Home Assistant (devices, users, automations, history) stays in its Longhorn volume, which VolSync backs up.
- **A local voice assistant**: Assist's "Local" pipeline is all on arda, with no cloud. Whisper turns speech into text and Piper speaks the answer, each its own Deployment. In between, Home Assistant's own intent matching handles plain commands ("turn off the kitchen lights") in a fraction of a second. Anything it doesn't understand goes to Ollama, a local LLM (`qwen3:4b-instruct` on CPU) that may also control the house, which answers in a few seconds.
- **Matter** goes through the Matter Server, a sidecar in Home Assistant's pod so it shares the host network and moves with it. It listens only on localhost, because its API has no login. **Google Cast** is added too, for the speakers and Chromecasts.
- **Logging in with Dex**: Home Assistant has no OIDC of its own, so the [hass-oidc-auth](https://github.com/christiaangoossens/hass-oidc-auth) component adds it, installed from a pinned, hash-checked release into the volume. The login page offers Dex beside the usual username and password. Dex's `admin` is linked to the owner `admin`; anyone else Dex knows gets an ordinary user of their own. It is not a Dex login in front of the site, which would break the companion apps.
- **The companion app** logs in with a code: it shows one, you sign in with Dex in a browser and type it in. Or it uses the owner's username and password directly, the fallback that always works.
- Python 3.13 and later reject the lab CA, which has no keyUsage extension. A `sitecustomize.py` relaxes that one check for `*.kidd.network` only, as Paperless's does, until the CA is re-issued.

#### Media
[`src/manifests/arda/media.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/media.yml)
- Films and series, from asking to watching, on the LAN only: **Seerr** (`seerr.kidd.network`) takes requests and hands them to **Sonarr** (series) and **Radarr** (films) (and books, comics and manga to the apps below), which search the indexers **Prowlarr** gives them, send what they pick to **qBittorrent**, and file the result into the library; **Bazarr** adds subtitles; **Jellyfin** and **Plex** play it. Seerr is Overseerr and Jellyseerr merged, so one request app serves both players.
- The Dex login guards Prowlarr, Sonarr, Radarr, Bazarr and qBittorrent, with their own logins off. Seerr, Jellyfin and Plex keep their own users, since requests and watch history belong to a person and the TV apps can't do a browser login.
- **qBittorrent only reaches the internet through Mullvad.** A gluetun sidecar in its pod holds a WireGuard tunnel and a firewall that drops everything else, so if the tunnel drops, so does qBittorrent's traffic. Only that one pod uses the VPN: the rest of arda, games and the Cloudflare tunnel included, goes out as normal. Without a Mullvad key in `.env` it doesn't start at all.
- **One volume, one layout.** Downloads and library share a single volume, mounted at `/data` in every app (`torrents/` and `media/`, after TRaSH's guides), so an import is a hardlink: instant, and no second copy. For now it’s a 200 GiB Longhorn volume, mirrored on the two 1 TB SSDs and shared over NFS (ReadWriteMany), so the media apps run on any worker rather than all on one; it’s left out of the nightly backups (a library can be fetched again; each app's own settings are backed up). The NAS will replace it with an NFS volume of the same name, without the apps changing.
- How the apps know each other is set up for them: fixed API keys (derived from one `.env` value), Bazarr's settings written before it starts, and a CronJob that adds the rest through each app's API every 15 minutes. Indexers are deliberately left empty, to be chosen in Prowlarr.
- Transcoding is on the ProDesks' Intel GPUs (Quick Sync), through the `i915` Talos extension, with the media apps on a worker. Some units reset themselves a couple of minutes after booting with that driver until two kernel arguments turned off the GPU's display power-saving states and kept it out of VT-d; every node gets those now.

#### Books, comics, manga and audiobooks
[`chaptarr.yaml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/media/chaptarr.yaml), [`comicarr.yaml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/media/comicarr.yaml), [`grimmory.yaml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/media/grimmory.yaml), part of the media app
- Fetched by an *arr, read in one place. Asking is done in Chaptarr and Comicarr themselves for now: Seerr has no books or comics. **Chaptarr** (`chaptarr.kidd.network`) does books and audiobooks, a Readarr fork that keeps both formats of a title in one instance; **Comicarr** (`comicarr.kidd.network`) does comics and manga, Mylar3's successor, with MangaDex for manga. Both search through Prowlarr and download through the same qBittorrent and VPN, into `/data/media/books`, `audiobooks`, `comics` and `manga` on the shared volume.
- **Grimmory** (`grimmory.kidd.network`) is the reader for all four: books, comics, manga and audiobooks in one library, with Kobo and KOReader sync, OPDS and send-to-Kindle. It's behind the users' Dex login, so friends and family can use it, and has no login of its own: it makes an account from the Dex login on a first visit, and LLDAP's admins are its admins. Anything dropped into `/data/media/bookdrop` is imported.
- Chaptarr and Comicarr are behind the admin Dex login; Comicarr asks for its own login after it too (user `admin`), having no way to trust Dex's.
- Comics search needs a free ComicVine API key (`ARDA_COMICVINE_API_KEY` in `.env`); manga search works without one.

#### Paperless
[`src/manifests/arda/paperless.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/paperless.yml)
- Paperless-ngx at `paperless.kidd.network`, at home and through the tunnel: paperwork from the phone, from email and, later, from a scanner is OCR'd, tagged and searchable. The documents, database and search index live on Longhorn, so VolSync backs them up nightly to R2, encrypted by restic. That matters here: these are ID and bank documents.
- Kept small for arda's memory: SQLite rather than Postgres (one household's paperwork is well within it), a Valkey broker in the same pod, one task worker, and no Tika or Gotenberg. PDFs and images need neither; Office files and mail bodies (`.eml`) would. It uses about 600 MiB at rest.
- **Logins.** "Sign in with Dex" on the login page (Dex client `paperless`). The first Dex sign-in creates a Paperless user, and a CronJob makes it an admin within ten minutes. There is also a local superuser, `paperless`, with `ARDA_PAPERLESS_ADMIN_PASSWORD`. With Dex off the tunnel for now, the Dex button only works at home; Paperless's own login works anywhere.
- **Phone.** The Paperless Mobile (Android) and Swift Paperless (iOS) apps upload over HTTPS. Server `https://paperless.kidd.network`, at home or away. The apps can't do a Dex login, so give them a password or a token. Either use `paperless` and its password, or, as your Dex user, open *My Profile* in the web app and set a password there, or create an *API Auth Token* (Swift Paperless accepts a token).
- **Email.** Optional: set `ARDA_PAPERLESS_MAIL_HOST`, `_USER` and `_PASSWORD` (and `_PORT` or `_FOLDER` if not 993 and `INBOX`). The CronJob then creates the mail account and rule `inbox`. PDF and image attachments in that folder are consumed and the mails marked read, checked every ten minutes. Use a mailbox of its own, such as a new Gmail address with an app password, and forward paperwork to it. Without those values the rule stays off. More rules, such as other folders, senders or tags, can be added in the web app's *Mail* page, and the CronJob leaves them alone.
- **Scanner (when there is one).** Paperless's consume folder is also an SMB share, on the LAN only: `\\192.168.1.58\scan` (or `\\paperless.kidd.network\scan` at home). In the scanner's *scan to network folder* / *scan to SMB* settings: host `192.168.1.58`, share or path `scan`, user `scanner`, password `ARDA_PAPERLESS_SCANNER_PASSWORD`, domain `WORKGROUP` or blank, port 445, PDF at 300 dpi. Anything saved there is consumed within seconds and removed from the share.
- **SMB or email for a scanner?** Scan-to-email is the more dependable choice for typical home scanners and printers. Nearly all of them can do it, it works from anywhere, and it needs only the mailbox above. Scan-to-SMB is quicker and stays on the LAN, but many older or cheaper devices only speak SMB1, which this share refuses (SMB2 or newer only). If a scanner offers SMB2/3, use the share. If it offers only SMB1, use email.

#### Public utilities
[`src/manifests/arda/tools.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/tools.yml)
- IT-Tools at `it-tools.kidd.network` and CyberChef at `cyberchef.kidd.network`, on the internet with no login and under Utilities on the public Homepage at `kidd.network`.
- Safe to publish because they're static pages that do all their work in the visitor's browser: nothing is uploaded, stored, or fetched by the server. That's the test for anything else published without a login. File drops, pastebins, server-side converters and anything that fetches a URL a visitor gives it stay behind Dex.
- Both run as non-root nginx on a read-only filesystem. IT-Tools' image runs nginx as root, so only its built site is taken from it, copied into unprivileged nginx at start.

#### MeTube and Transmute
[`src/manifests/arda/metube.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/metube.yml), [`src/manifests/arda/transmute.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/transmute.yml)
- **MeTube** at `metube.kidd.network`: a web page for yt-dlp. Paste a link (YouTube and 1,000+ other sites), pick video or audio and a quality, and save the file from its Completed list. No accounts, no library, no database; files and the list are kept a week, then deleted (MeTube's own setting, and a sidecar that removes anything older). yt-dlp updates to its newest build nightly. 20 GiB of scratch space, not backed up.
- **Transmute** at `transmute.kidd.network`: converts and compresses images, video, audio, documents, spreadsheets, subtitles and fonts, all on arda. Its own accounts are off: past the Dex login each browser goes straight into its own guest workspace, kept 30 days, with no login page (a script patched into its page opens the guest session before the app starts). Its `admin` account (made automatically, so guests work from the first visit; password in the `transmute` Secret) is for its settings. Its 20 GiB of scratch space isn't backed up.
- Both on the LAN only, behind the Dex login, on the private Homepage. Neither goes on the tunnel: one fetches whatever URL it's given, the other takes uploads and spends arda's CPU on them.

#### Dex login
[`src/manifests/arda/oauth2-proxy.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/oauth2-proxy.yml)
- One login for all of arda's sites, with ainur's Dex as the only place users are kept. A single oauth2-proxy acts as a Traefik forward-auth Middleware; a site opts in with one Ingress annotation, `traefik.ingress.kubernetes.io/router.middlewares: oauth2-proxy-dex@kubernetescrd`.
- The login's callback is `auth.kidd.network`, and its cookie covers all of `kidd.network`, so one login does for every site.
- arda's own consoles are on the LAN only: Longhorn at `longhorn.kidd.network` and Goldilocks at `goldilocks.kidd.network`, behind this login since they have none of their own. arda's apps are in ainur's Argo CD, at `argocd.kidd.network`.
- Every arda service is on one of the two Homepages: an Ingress or a Service annotated `gethomepage.dev/enabled` is copied to ainur's Homepage every five minutes. A Service, like Dragonwilds' game port, has no web page, so it needs `gethomepage.dev/href`.
- ainur's sites go out through arda's tunnel too, since ainur has none: annotate an ainur Ingress `kidd.network/tunnel: "true"`, as on arda, and ainur's `arda-tunnel` CronJob copies it onto arda within five minutes, forwarding its hosts to ainur. Dex, Grafana, Headlamp and Argo CD are published this way, each behind its own Dex login, so the login works from anywhere.

#### LAN HTTPS
[`traefik/values.yaml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/traefik/values.yaml)
- At home, arda's sites resolve to arda itself, not the tunnel. arda's Traefik answers them with a `*.kidd.network` certificate from the lab CA, which ainur's cert-manager makes and ainur's `arda-bootstrap` Job copies over, so a device that trusts the lab CA trusts arda's sites as it does ainur's.

#### Cloudflare
[`cloudflared.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/cloudflared.yml), [`external-dns.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/external-dns.yml), [`external-dns-tunnel.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/external-dns-tunnel.yml), [`ddns.yml`](https://github.com/andrewiankidd/project-iluvatar/blob/main/src/manifests/arda/ddns.yml)
- Web traffic comes in through a Cloudflare Tunnel, which publishes only the Ingresses that opt in (`kidd.network/tunnel: "true"`).
- Game ports can't use the tunnel, so their records point at the home address, which ddns keeps current, and the router forwards them.
